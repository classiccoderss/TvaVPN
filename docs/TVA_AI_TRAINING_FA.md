# پایه دانشی TVA AI

این سند، مرجع طراحی دستیار Gemini در TVA VPN است. این روش «آموزش مجدد مدل» یا Fine-tuning نیست؛ برنامه در هر درخواست، دستورالعمل اختصاصی TVA و خلاصه امن تنظیمات فعلی را به‌عنوان System Instruction و context می‌فرستد. Gemini در API از `systemInstruction` پشتیبانی می‌کند و برای پاسخ ساختاریافته نیز می‌توان از JSON Schema استفاده کرد.

## آنچه دستیار باید بداند

- TVA یک برنامه اندرویدی مبتنی بر موتور Aether و مسیر VPN/TUN است.
- پروتکل‌های موجود در سورس: `AUTO`, `MASQUE`, `WIREGUARD`, `GOOL`, `MIM`.
- Backendهای موجود: `AETHER`, `AETHER_PSIPHON`, `TOR`, `AETHER_TOR`, `TOR_PSIPHON`, `TOR_AETHER`.
- در حالت معکوس `TOR_AETHER` پروتکل مؤثر WARP، `MASQUE` است.
- حالت‌های انتخاب Endpoint: `AUTO`, `MANUAL_PEER`, `MANUAL_RANGE`.
- حالت‌های اسکن: `TURBO`, `BALANCED`, `THOROUGH`, `STEALTH`, `IRONCLAD`.
- IP family: `V4`, `V6`, `BOTH`.
- Noize: `OFF`, `LIGHT`, `FIREWALL`, `BALANCED`, `GFW`, `AGGRESSIVE`.
- MTU پیش‌فرض 1280 است. پیشنهاد AI بدون نتیجه اندازه‌گیری MTU باید در بازه 1280 تا 1500 بماند.
- Keepaliveهای قابل انتخاب: `0`, `10`, `25`, `45` و فقط برای WireGuard/GOOL صریح معنا دارد.
- TLS fragmentation presetها: `DEFAULT`, `LIGHT`, `BALANCED`, `AGGRESSIVE` با مقادیر ثابت موجود در کد.
- `fastEndpointOnly` به‌طور پیش‌فرض خاموش است؛ روشن کردن آن ممکن است باعث رد کردن Endpoint سالم و شروع اسکن طولانی شود.

## مرزهای امنیتی

Gemini فقط پیشنهاد می‌دهد. هیچ پاسخی از مدل مستقیماً روی تنظیمات نوشته نمی‌شود. برنامه فقط ۹ شناسه مجاز را می‌پذیرد: `mtu`, `protocol`, `scanMode`, `ipVersion`, `noize`, `keepalive`, `fragmentPreset`, `quickReconnect`, `fastEndpointOnly`.

تغییر Backend، Kill Switch، Strict Kill Switch، محافظت IPv6، قوانین برنامه‌ها، DNS دلخواه، routeها، پراکسی‌ها، Tor/Psiphon، Zero Trust، کلیدها، توکن‌ها و محتوای کانفیگ‌ها از اختیار مدل خارج است.

هر پیشنهاد حداکثر سه تغییر دارد. برنامه باید همه تغییرات را یکجا اعتبارسنجی کند؛ اگر یکی نامعتبر بود، کل پیشنهاد رد می‌شود. فقط بعد از تأیید کاربر، snapshot تنظیمات قبلی ذخیره و تغییرات اعمال می‌شوند. امکان بازگشت به snapshot قبلی باید در UI وجود داشته باشد.

## حریم خصوصی

- API Key فقط در `SecretStore` مبتنی بر Android Keystore نگهداری شود.
- هرگز API Key یا رمز/توکن‌های اتصال در prompt، history، گزارش یا لاگ ثبت نشود.
- برای تحلیل لاگ از `AiRedaction.digest(...)` استفاده شود؛ لاگ خام فرستاده نشود.
- profile context فقط مقادیر لازم و امن را ارسال می‌کند؛ مقدار DNS، آدرس peer، آدرس upstream، شناسه Zero Trust و credentialها حذف می‌شوند.
- محتوای لاگ یا کانفیگ، دستور سیستمی نیست و نباید به‌عنوان دستور اجرا شود.

## مسیر ارتباط Gemini

درخواست‌های AI باید از مسیر اختصاصی Psiphon محلی عبور کنند و نباید برای این کار، Backend یا تونل اصلی کاربر تغییر کند. برنامه باید پیش از ارسال، وجود listener اختصاصی را از وضعیت runtime تأیید کند. شماره پورت ثابت نباید hard-code شود؛ از PortLease/وضعیت واقعی سرویس استفاده شود. اگر مسیر اختصاصی آماده نیست، درخواست fail-closed شود و از مسیر مستقیم یا تونل اصلی fallback نکند.


## پیاده‌سازی رابط و اتصال (نسخه فعلی سورس)

- صفحه `TVA AI` از منوی کناری صفحه اصلی باز می‌شود و صفحه تنظیمات مستقل دارد.
- کاربر کلید شخصی Gemini و شناسه مدل را وارد می‌کند. مقدار کلید با `SecretStore` و AES-GCM مبتنی بر Android Keystore نگهداری می‌شود؛ ذخیره‌سازی با خواندن دوباره و تطبیق مقدار تأیید می‌شود. خالی‌کردن فیلد کلید و زدن «ذخیره» کلید قبلی را پاک می‌کند.
- مقدار پیش‌فرض مدل `gemini-3.8-flash` است؛ شناسه مدل قابل ویرایش و اعتبارسنجی محلی است.
- دکمه «آزمایش اتصال» ابتدا مسیر مستقل Psiphon را آماده می‌کند و سپس یک درخواست واقعی `generateContent` به Gemini می‌فرستد؛ صرف باز بودن پورت SOCKS به‌عنوان موفقیت API گزارش نمی‌شود.
- `AiPsiphonRouteManager` یک فرایند جداگانه از `libaether.so` را با حالت `--psiphon-only`، پورت loopback تصادفی، دایرکتوری کاری مستقل و datastore مستقل اجرا می‌کند. این کار `VpnService` دوم نمی‌سازد و Backend یا پروفایل تونل اصلی را تغییر نمی‌دهد.
- کلاینت Gemini فقط به `127.0.0.1:<AI-SOCKS-PORT>` متصل می‌شود و مقصد `generativelanguage.googleapis.com:443` را با SOCKS5 به‌صورت hostname درخواست می‌کند تا resolve مقصد در سمت خروجی Psiphon انجام شود. هیچ fallback مستقیم یا از مسیر تونل اصلی وجود ندارد.
- چون خود بسته TVA در پیاده‌سازی TUN از تونل خودش مستثنا شده تا حلقه مسیریابی ایجاد نشود، این فرایند جانبی نیز از مسیر شبکه فیزیکی دستگاه به Psiphon دسترسی می‌گیرد. حالت Always-on VPN با lockdown، محدودیت‌های OEM و شبکه‌هایی که خروجی مستقیم را مسدود می‌کنند ممکن است مانع این مسیر شوند؛ باید روی دستگاه واقعی تست شود.
- به Gemini خلاصه امن تنظیمات و وضعیت کلی اتصال (بدون IP محلی و جزئیات خصوصی خطا) فرستاده می‌شود. تحلیل لاگ فقط پس از پالایش `AiRedaction.digest` ارسال می‌شود.
- تغییر تنظیمات فقط از allow-list محلی می‌گذرد؛ هیچ ابزار فراخوانی مستقیمی به Gemini برای نوشتن فایل یا اجرای فرمان داده نشده است. اعمال و راه‌اندازی مجدد تونل فقط پس از تأیید صریح کاربر انجام می‌شود.
- خروج از صفحه TVA AI، فرایند جانبی Psiphon همان صفحه را متوقف می‌کند؛ این توقف ارتباطی با تونل VPN اصلی ندارد.

### نکته درباره «آموزش» مدل

این پیاده‌سازی وزن‌های Gemini را fine-tune نمی‌کند. رفتار تخصصی با دستورالعمل `TvaAiKnowledge.systemInstruction`، مشخصات واقعی پروفایل و وضعیت runtime در هر درخواست، و اعتبارسنجی قطعی داخل برنامه فراهم می‌شود. بنابراین نسخه‌های جدید TVA باید دستورالعمل و schema را همراه با تغییرات واقعی سورس به‌روزرسانی کنند.
